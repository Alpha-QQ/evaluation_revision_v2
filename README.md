# Joint Same-Index Evaluation Artifact

This repository contains the cryptographic-core implementation and recorded
measurements used by the manuscript's evaluation of the proposed DID/VC
candidate-obfuscation workflow.

## Contents

- `proposed.py`: URS conversion, joint same-index binding proof, and SDVS.
- `benchmark_candidate_sizes.py`: latency, Python-traced memory, and serialized
  artifact-size benchmark over candidate-set sizes 50, 100, 200, and 500 and
  disclosed-attribute counts 1--20.
- `saliency_analysis.py`: classifier-based decoy-saliency experiment.
- `intersection_analysis.py`: synthetic candidate-set intersection experiment.
- `run_all_experiments.py`: unified experiment runner.
- `test_proposed_protocol.py`: protocol acceptance and rejection tests.
- `test_experiments.py`: experiment input and completeness tests.
- `results/all_results.json`: complete recorded output, including raw performance
  rows, summaries, seeds, environment metadata, source hashes, and completeness
  checks.

## Scope

The measured implementation is the joint same-index cryptographic core. Its
single Fiat--Shamir Sigma-OR proof binds the issuer-signature response, holder
key, and presentation key to the same hidden candidate index. The outer SDVS
covers the complete canonical message containing that proof.

The benchmark uses distinct issuer keys and raw public keys as synthetic inputs.
The public keys represent keys already obtained from DID resolution; the code is
not a DID resolver. The `valid_until` value is a fixed issuer-signed benchmark
field used for equality checking and is not the manuscript's negative-only
revocation-list mechanism. Network access, live DID resolution, revocation-list
retrieval, and nonce-state management are outside the measured workflow.

`verify_urs_dvs` returns `(accepted, binding_diagnostic)` for testing. Only the
first value is the aggregate protocol acceptance result; candidates are not
individually verified or exposed as separate verification outputs.

## Reproduce

Use 64-bit CPython 3.9 or newer:

```text
python -m venv .venv
python -m pip install -r requirements.txt
python -m unittest discover -p "test_*.py" -v
python run_all_experiments.py
```

The unified runner writes `results/all_results.json`. A short smoke run is:

```text
python run_all_experiments.py \
  --candidate-sizes 50 \
  --attribute-counts 1,20 \
  --repeats 2 \
  --saliency-train-lists 20 \
  --saliency-test-lists 50 \
  --intersection-trials 100 \
  --output results/smoke_all_results.json
```

The recorded result contains 16,000 raw performance rows, 160 performance
summary rows, eight saliency rows, ten intersection summary rows, and explicit
completeness checks. The source hashes in that file identify the exact measured
Python files and dependency snapshot in this commit.

The SD-JWT, BBS+, and zk-SNARK values retained for context in the manuscript are
legacy comparison measurements and are not regenerated by this dependency set.
